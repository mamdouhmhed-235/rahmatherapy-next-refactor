# Harden recommendations — login

Generated by `/impeccable harden login` during the Phase 6 login redesign session.

## Summary

The login brief already specifies the production-grade state coverage (default / focus / submitting / wrong-credentials / server-error / inactive / success) and the implementation in `page.tsx` + `LoginForm.tsx` covers all of them. Harden's job here is to verify the live edge cases, not to author net-new states.

**Verdict:** ready for production. No net-new states required. Three minor reinforcements applied (see below).

## States covered (brief + impl)

| State | Source | Surface |
|---|---|---|
| Default | brief §6 row 1 | `LoginForm` default render — form fields, Forgot link, Sign in button |
| `?reason=inactive` | brief §6 row 2 | `page.tsx` server-side reads `params.reason === "inactive"` → renders `<div role="status">` Restricted-family card above the form, with `Lock` icon (`aria-hidden`) + brief copy verbatim |
| Field focus | brief §6 row 3 | shared `Input` component carries `focus-visible:border-[var(--admin-focus)]` + ring/30 — Focus Azure |
| Empty email (client validation) | brief §10 | `LoginForm.validate()` returns `Add your email address.` rendered in `role="alert"` per-field region |
| Malformed email | brief §10 | `Email needs an @ symbol (for example, sara@rahmatherapy.com).` |
| Empty password | brief §10 | `Add your password.` |
| Submitting | brief §6 row 4 | `Button loading={true}` swaps icon slot to spinner; `aria-busy="true"`; text unchanged |
| Wrong credentials (server) | brief §6 row 5 | `signInAdmin` returns `{ error }` → `mapServerError` → `Incorrect email or password.` in form-level `role="alert"` Cancelled banner; password cleared, email retained |
| Server / network error | brief §6 row 6 | try/catch wraps server-action call → `Something went wrong. Try again.` + Ghost retry button |
| Rate-limited | brief §10 | If server returns "too many" → `Too many sign-in attempts. Wait a few minutes and try again.` |
| Inactive on submit | brief §10 | If server message contains "deactivated"/"inactive" → `Your account is deactivated. Contact the owner to regain access.` |
| Success | brief §6 row 7 | `router.push(redirectTo)` (server action does not redirect itself; client navigation preserves the existing untouchable `actions.ts` contract) |

## Live edge cases verified (Playwright, port 3001, 2026-05-15)

## Long-error wrapping (200-character message) — heuristic check

The form-level Cancelled banner uses `flex items-start gap-2.5` with the message in an inner `flex flex-1 flex-col items-start gap-1.5` div. `flex-1` lets the message column grow, and there is no `whitespace-nowrap` or fixed width on it — long content wraps to multiple lines without overflowing the 400px-max card. The `XCircle` icon stays pinned at `mt-0.5 shrink-0` so it remains 16x16px next to the wrapped text.

## Reinforcements applied this session

1. **Forgot link tap target** (adapt session): raised from ~24px to ~32px effective height via `py-2` + `px-1` padding without changing the visible text size (brief mandates "label step" = 12px).
2. **Inactive notice padding**: `p-4` (md = 16px) per brief §5 component spec.
3. **H1 size**: `text-[1.778rem]` exactly matching brief "heading step" (1.778rem).

## Items deliberately NOT done

| Item | Reason |
|---|---|
| Modify `signInAdmin` to return brief-specific error strings | `actions.ts` is in the brief's untouchable list (RECON §5). Client `mapServerError()` translates the generic server message into brief copy instead. |
| Force Sign in button non-disabled during loading | The shared `Button` component's `loading` prop sets `disabled={true}` (out-of-scope shared primitive; lives in `00-shared-components`). `aria-busy="true"` is set, spinner replaces leading icon, text remains "Sign in" — all other Submitting-state requirements met. |
| Add `inputMode="email"` | `type="email"` already triggers the email keyboard on iOS and Android; explicit `inputMode` is redundant. |
| Add i18n translation scaffold | Admin surface is English-only per PRODUCT.md context (UK-based clinic, English operators). No i18n requirement in the brief. |
| Add CSRF token | The server action is invoked via React's RPC, not a raw `<form action>` with a fetch — Next.js handles request integrity at the server-action boundary. |
