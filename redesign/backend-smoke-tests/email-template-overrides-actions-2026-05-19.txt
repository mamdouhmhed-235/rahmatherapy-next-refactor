SCENARIO 4 — Invalid templateId (negative path)
------------------------------------------------------------------------------

Live-verification attempt:
  - Tried to corrupt the manual-send form's hidden `template_id` input to
    "not_a_real_template" via JS (React-aware setter + input event).
  - React's controlled input restored the original value before submit.
  - The form's `action` attribute is rendered as `javascript:throw new Error(...)`
    — Next.js / React intercepts submission via an internal action ID; the
    real action endpoint is not externally addressable from a temporary
    unbound form.
  - DB cross-check (filtered: created_at > 14:54:53.66415, after the
    Scenario-3 baseline): zero subsequent audit rows with any template_id
    other than the legitimate Scenario-3 "booking_confirmation" row. No
    Resend send was triggered with an invalid template id.

Code-inspection verification — actions.ts:
  Function: sendTemplateManually
  After the permission check (which returns "Insufficient permissions."
  if MANAGE_EMAIL_TEMPLATES is missing), the next operative lines are:

    const templateId = String(formData.get("template_id") ?? "");
    const template = findTemplate(templateId);
    if (!template) {
      return { ok: false, error: "template_not_found" };
    }

  This return is the FIRST exit after permission check. It precedes:
    - recipient validation
    - required-vars check
    - business_settings read
    - resolveTemplateOverrides() call
    - renderForTemplate() dispatch
    - getFromEmail() startup check
    - sendEmail() Resend POST
    - audit_logs.insert()

  Therefore, when the action is invoked with an invalid templateId, the
  return shape is `{ ok: false, error: "template_not_found" }` and NEITHER
  a Resend call NOR an audit row is written.

  The UI consumes state.error in ManualSendSheet's useEffect and surfaces
  it via `toast.error(state.error, { duration: Infinity })`, so the
  operator would see "template_not_found" persist until dismissed.

Verdict: VERIFIED BY CODE INSPECTION + DB CROSS-CHECK. Live UI exercise
         was blocked by React's controlled-input restoration; an in-product
         negative-path test would require either a Vitest unit test that
         invokes sendTemplateManually directly with forged FormData, or a
         dev-only endpoint to mount the action. Both deferred to a future
         pass. The negative-path code is small (4 lines) and proof obligations
         (Resend not called, audit not written) are satisfied by the
         early-return structure.
