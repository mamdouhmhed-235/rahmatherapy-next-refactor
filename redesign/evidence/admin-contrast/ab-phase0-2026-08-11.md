# Phase 0 A/B — isolating the effect of the de-alias from overnight data drift

**Run 2026-08-11.** Three sweeps, same harness, same routes, same roles.

The naive before/after (committed baseline vs post-Phase-0) showed light-mode failures rising by 367. That comparison is **confounded**: the committed baseline was captured on 2026-08-10 against different live data. This A/B separates the two causes by re-running the *pre-Phase-0* `tokens.css` against *today's* data.

| Measurement | tokens.css | data |
|---|---|---|
| **A** | pre-Phase-0 | 2026-08-10 (the committed 2,615 baseline) |
| **C** | pre-Phase-0 | 2026-08-11 (today) |
| **B** | post-Phase-0 | 2026-08-11 (today) |

`A → C` isolates **data drift**. `C → B` isolates **the de-alias**, which is the only thing that changed between them.

## Per role / theme

| Role | Theme | A | C | B | drift (A→C) | de-alias (C→B) |
|---|---|---:|---:|---:|---:|---:|
| OWNER | dark | 595 | 594 | **383** | −1 | **−211** |
| OWNER | light | 467 | 555 | **572** | +88 | **+17** |
| ADMIN | dark | 577 | 576 | **381** | −1 | **−195** |
| ADMIN | light | 441 | 518 | **594** | +77 | **+76** |
| COORDINATOR | dark | 202 | 202 | **63** | 0 | **−139** |
| COORDINATOR | light | 216 | 234 | **299** | +18 | **+65** |
| THERAPIST_A | dark | 59 | 59 | **15** | 0 | **−44** |
| THERAPIST_A | light | 56 | 56 | **82** | 0 | **+26** |
| UNAUTHENTICATED | both | 2 / 0 | 2 / 0 | 2 / 0 | 0 | 0 |

## Totals

| | dark | light | all |
|---|---:|---:|---:|
| **A** — old tokens, old data | 1,433 | 1,180 | 2,615 |
| **C** — old tokens, today | 1,431 | 1,363 | 2,796 |
| **B** — new tokens, today | **842** | **1,547** | **2,391** |

- **Data drift (A→C): dark −2, light +183.** Overnight data movement alone added 183 light-mode findings. Dark was essentially inert.
- **The de-alias (C→B): dark −589, light +184.** Net **−405 (−14.5%)** against a same-day control.

## What this establishes

1. **The light-mode regression is real and is caused by the de-alias — but it is +184, not +367.** Almost exactly half the naive figure was overnight data drift that the stale baseline would have misattributed to the change.
2. **The dark-mode improvement is real and large: −589 (−41%).** Unaffected by drift.
3. **Net, the de-alias is a substantial improvement** — but it is not the strict "light must not worsen" the plan's Step 0.1 verify predicted, and that prediction is now known to be wrong.

## Methodology finding — the baseline is perishable

`A → C` moved by +181 net with **no code change at all**. Any future comparison against a stored Layer 3 baseline must re-run the control on the same day, or it will attribute data drift to the code under test. The plan's expected-trajectory note ("Phase 0 should move 2,615 sharply") assumes a stable baseline that does not exist.

**Also note:** `e2e/admin-contrast-helpers.ts` persists only the 15 worst findings per role/theme (`.slice(0, 15)`), so a full per-finding diff is not recoverable from the artifacts — only per-route counts and the worst 15.

## The remaining hypothesis, not yet proven

The new light-mode failures pair a **light-theme foreground with a dark-theme background on the same element** (e.g. `#151b18` on `rgb(28,26,22)`, the dark value of `--admin-surface`), and the reverse. Before the de-alias these tokens were *uniformly* frozen at light values, so foreground and background were at least mutually consistent; now backgrounds track the theme while text colour on `<a>` elements is still frozen by **D12** — the unlayered `a { color: inherit }` in `site-parity.css` that defeats every Tailwind text-colour utility.

If that is the mechanism, **Step 0.3 is the fix, and Steps 0.1 and 0.3 are not independent** — contrary to the plan, which schedules 0.3 as separable. This is testable: apply Step 0.3 and re-run. The light total should fall sharply.
