# PART 4 — ENVIRONMENT + DISCIPLINE CARRY-FORWARD

## 4.1 Dev environment gotchas
- If buttons silently don't fire on first session test: nuke `.next` + restart `pnpm dev` **before** deeper diagnosis.
- If a server action returns OK but DB doesn't change: check dev server **terminal stdout** for CHECK constraint violations (PG `23514`). Don't assume Turbopack caching — H4 lesson cost 2 hours.
- **Server-action RLS denial pattern (R4 cost ~15 min):** if a server action gets `permission denied for table X`, the cause is missing DML grants — NOT an RLS-policy bug. The codebase's convention is `grant ... to service_role` (admin client writes), not `to authenticated`. Always check existing migrations like `phase16_service_role_grants.sql` before switching to RLS-scoped writes; switch the action to use `createSupabaseAdminClient()` and manually scope on `staff_id = profile.id`.
- If a permission gate appears to fail silently: add temporary `console.error(...)` at **each gate position**, not just at the end. Errors propagate to dev server stdout, not browser console.
- If Turbopack staleness recurs on R1/R2 (many new actions), consider `next dev --no-turbopack` in `next.config.ts`.
