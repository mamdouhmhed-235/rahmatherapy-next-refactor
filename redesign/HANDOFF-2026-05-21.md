## 1.8 Band B reframe — session 4 (research + direction, no implementation)

**Output:** `redesign/BAND-B-RESEARCH-2026-05-22.md` — the canonical research + brainstorm artefact. Read top-to-bottom before writing any Band B brief. Does NOT replace the existing dashboard / reports briefs; sits beside them as the strategic frame.

### What the user reframed
- The current post-Phase-6 Dashboard and Reports feel dead, unprofessional, and look bad — **not** the pre-Phase-6 state the previous session-bridge assumed. Spacing/alignment/sizing/colour are off. Cards inconsistent. Visuals unmodern.
- **Per-user metric tracking is missing as a first-class concept.** Every operator (Owner / Admin / Coordinator / Therapist) should be able to see their own granular numbers — bookings handled, revenue brought in, retention, etc. Owner/Admin additionally want a macro lens that overlays everyone.
- The "where does my own data live" question is the architectural one. Industry resolves it via a triad: **Dashboard (today)** + **Reports (business macro + drill)** + **per-staff Performance page (the missing third surface)**.

### What the research surfaced
- Triad pattern is universal across SimplePractice, Jane App ("Practitioner Dashboard"), Cliniko, TherapyNotes, Mindbody, Mangomint. We have surfaces 1 + 2; surface 3 doesn't exist.
- Industry-canonical KPIs (utilisation rate, no-show rate, retention rate, net collection rate, source attribution, avg booking value) — ~70% computable from existing tables; ~30% needs additive helpers or a small migration.
- Modern dashboard rules (2026): 5–9 cards on first paint, 40-30-20-10 space rule, tile = number + delta + sparkline, skeleton-shimmer not pulse, semantic 5–9 hue charts.
- Chart-library decision pending: Tremor (Recharts-based shadcn-styled wrapper, ~50kB) vs hand-rolled theming layer on raw Recharts.

## 4.1 Dev environment gotchas
- If buttons silently don't fire on first session test: nuke `.next` + restart `pnpm dev` **before** deeper diagnosis.
- If a server action returns OK but DB doesn't change: check dev server **terminal stdout** for CHECK constraint violations (PG `23514`). Don't assume Turbopack caching — H4 lesson cost 2 hours.
- **Server-action RLS denial pattern (R4 cost ~15 min):** if a server action gets `permission denied for table X`, the cause is missing DML grants — NOT an RLS-policy bug. The codebase's convention is `grant ... to service_role` (admin client writes), not `to authenticated`. Always check existing migrations like `phase16_service_role_grants.sql` before switching to RLS-scoped writes; switch the action to use `createSupabaseAdminClient()` and manually scope on `staff_id = profile.id`.
- If a permission gate appears to fail silently: add temporary `console.error(...)` at **each gate position**, not just at the end. Errors propagate to dev server stdout, not browser console.
- If Turbopack staleness recurs on R1/R2 (many new actions), consider `next dev --no-turbopack` in `next.config.ts`.
- **Creating an `auth.users` row by raw SQL (Zone-2 — only with explicit user authorisation):** the bcrypt password produced by `crypt(password, gen_salt('bf', 10))` IS Supabase-compatible. GoTrue's "Invalid credentials" rejection on a freshly-inserted row with a valid-looking bcrypt hash is almost always caused by NULL values in `auth.users.{confirmation_token, recovery_token, email_change_token_new, email_change}` — set them to empty strings (`''`) explicitly when inserting. Also INSERT a paired `auth.identities` row (`provider='email'`, `provider_id=user_id::text`, `identity_data={"sub": ..., "email": ..., "email_verified": true}`). The B-0 plan's H2 warning that "raw `crypt()` doesn't produce a Supabase-compatible hash" is incorrect — discovered in session 5 cost ~10 min. Working pattern in session-5 B-0 step 5; reusable for future fresh-account creation.
- **Next 16 Turbopack omits per-route First Load JS from the CLI route table.** To extract bundle baselines, parse `.next/build-manifest.json` (rootMainFiles + polyfillFiles) + per-route `.next/server/app/<route>/page_client-reference-manifest.js` (the `entryJSFiles` field, after the `globalThis.__RSC_MANIFEST["..."] = ` assignment), then sum gzipped chunk bytes via Node `zlib`. Working script logic preserved in `redesign/per-page-progress/B0-baseline-progress.md`; throwaway script itself was deleted after generating `redesign/baselines/bundle-pre-B1.json` (no committed dep on it).
