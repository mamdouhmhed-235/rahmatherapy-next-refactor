## Therapist variant fullness pass — addressing the empty-feeling complaint

**The problem (user-flagged):**
> "The therapist variant of the dashboard now unless there is data present makes the dashboard look very empty and rudimentary. I want it to be a suitable production and business ready dashboard variant page for the therapist role and it shouldn't look or feel empty."

**Research input:**
- Empty states should be *actionable*, not just illustrative (Carbon, Mobbin, Toptal consensus).
- Worker apps (Uber Driver, DoorDash Dasher) fill idle screens with: earnings recap, tips, multi-app prompts, peak-hour suggestions, achievement milestones, profile prompts.
- Mental-health worker dashboards (TheraTrack) use customizable modular widgets so the page never feels bare.
- 2026 gamification consensus: streaks + milestones improve daily-active-use by 40–60% vs. single-mechanism; healthcare-specific implementations (provider-prescribed) outperform consumer-only.

**Refined Therapist variant — adds 5 content blocks that render meaningfully regardless of data sparsity** (full spec applied to B-5 brief §5 in this audit pass):

1. **Profile-readiness banner (PROMOTED from `<ProfileCompletionNudge>`)** — Currently hides when `profile_completed_at` is set OR all five fields are filled. Refined behaviour: even after completion, shows a slim "All set: ★★★★★ profile" celebratory pill for the first 7 days (positive reinforcement). Beyond 7 days, hides as today.

2. **Achievement / milestone callout** — Below the Personal Stripe. Single-line `<MetricRow>`-shaped row with `Trophy` lucide icon + plain-English milestone copy:
   - "You completed 18 visits last month — your best month yet."
   - "First visit completed — welcome to the team."
   - "5 same-gender requests fulfilled this week."
   - "10-visit streak with no cancellations."
   - When no milestones tripped: rotates to a working-tip from a static library ("Tap to call a client directly from the Next Visit card." / "Pull down to refresh the dashboard.").
   - Implementation: pure helper `getTherapistHighlightOrTip(scorecard, priorScorecard, profile)` in `therapist-fullness.ts` returning at most 1 highlight; falls back to deterministic tip pick based on `profile.id` hash modulo tip-library length. (Originally drafted as `getTherapistMilestones` with gamification framing; renamed post-Q1 tone resolution.)

3. **My recent clients** — Below Today's visits (or in its place when Today is empty). Horizontal scroll strip on mobile / 4-card grid on desktop. Shows last 6 unique clients seen in the last 30 days. Each card: avatar + first name + service + days-since-last-visit. Tap → client detail. Empty state (brand-new therapist with no clients): hides entirely.

4. **Open invitations to claim — promoted from "Claimable strip"** — Already exists. Refinement: when Today's visits + Next Visit are both empty, this becomes the *primary* visual element (renders earlier in the page flow + uses Attention family background-strong tint to invite engagement). When Today has visits, this stays in its current secondary position.

5. **Quick-help / resources panel** — Bottom of page (above Weekly summary). Single small panel: "Need help?" + 2–3 Ghost links per role need:
   - "View my availability" → `/admin/staff/{staffId}/availability`
   - "Update my profile" → `/admin/staff/{staffId}` (or `/admin/me` once B-3 ships → goes to Performance, but profile edit link is contextually different — link to staff edit form)
   - "Browse claimable work" → `/admin/bookings?view=claimable`
   - "View my completed visits" → `/admin/bookings?view=completed&staffId={ownId}`
   - Hide individual rows if they'd link to denied destinations (e.g. Inactive staff has no claimable access).

**Empty-state philosophy for Therapist variant** (codified in B-5 brief §6):
- "Empty" never means "blank screen". It means "the operational data slots are zero, but the surrounding scaffolding is full and actionable."
- Every empty section produces *one of*: an explanation, an actionable CTA, a tip, or a milestone — never just "—" or "No data."
- The page should look identical in *structure* whether the therapist has 0 visits or 8 visits today; only content changes.
